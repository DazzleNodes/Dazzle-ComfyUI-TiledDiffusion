# Phase R2 — Empirical: does base Qwen-Image accept `ref_latents` as a tile-coherence anchor?

> **Empirical finding (2026-04-28)**: Outcome **(c) — Broken**. Base Qwen-Image-fp8 produces garbled output with high-amplitude artefacts (magenta speckle, brick patterns, scan-line corruption) consistent with NaN-adjacent values propagating through attention to VAE decode. Sampling time also doubles (~450s vs ~225s for the same workflow without `structure_latent`) due to the attention sequence length doubling when ref tokens are concatenated. **Decision: do not promote `structure_latent` for base Qwen use; pivot to Phase R4 (noise-structuring) for a model-agnostic non-CN coherence anchor.** Path 1 (`structure_latent` input) ships marked experimental in case Qwen-Image-Edit users find value; Path 2 (Hi-Res Fix recipe at `denoise<1.0`) is the recommended path for base Qwen.

This is a research checklist, not a regression checklist. Its purpose is to discriminate between three possible inference behaviours of the **base Qwen-Image-fp8/fp16** checkpoints (i.e. the non-Edit variants) when fed `ref_latents` via ComfyUI's existing `ReferenceLatent` conditioning node.

The outcome of this checklist gates the next implementation phase:
- (a) **Graceful** — ref tokens contribute structural prior, tiles cohere → proceed to Phase R3 (build a `structure_latent` input on the TiledDiffusion node).
- (b) **Over-use** — tiles produce copy-paste artefacts of the low-res pre-pass → pivot to Phase R4 (noise structuring).
- (c) **Broken** — NaN, instability, garbled output → pivot to Phase R4. ← **observed outcome**

## Why this matters

The `rope_patch` in this fork fixes Flux T2I tile coherence by re-routing positional information through text↔image cross-attention. For **Qwen-Image base T2I** (no ControlNet, no reference latent) the same patch is empirically a thin lever — see the README "Pure-T2I tile coherence on Qwen-Image" section for the mechanism (RoPE relative-only inside self-attention).

One candidate fix is to inject a low-res structural prior through Qwen's existing `ref_latents` channel in `comfy/ldm/qwen_image/model.py`. The model's `_forward` accepts `ref_latents` unconditionally on variant — line ~456, the `if ref_latents is not None:` branch concatenates ref tokens to the image token sequence before the transformer blocks. Qwen-Image-Edit was *trained* with this conditioning; base Qwen-Image was not. Whether base Qwen-Image still uses the ref tokens *constructively* at inference is unverified.

This test answers that question with a small workflow before we commit implementation effort to a `structure_latent` input.

## Prerequisites

- ComfyUI running with this fork installed at `custom_nodes/ComfyUI-TiledDiffusion`
- **Qwen-Image-fp8-e4m3fn** (base, non-Edit) checkpoint loaded
- The matching Qwen-Image VAE
- (Optional, for outcome calibration) Qwen-Image-Edit checkpoint
- A prompt suitable for high-res rendering (detailed scene with one clear subject works best — e.g. `"a photograph of a lone tree on a windswept hillside, golden hour"`)
- A fixed seed for reproducibility (record it)

## Test plan — three workflows, same prompt and seed

Run all three in sequence. Save each output and the console log. The differences between them are the data.

### Workflow A — Baseline: tiled, no anchor

Standard tiled high-res pass with no structural prior at all. Expected to produce disjoint tiles per the README caveat. Establishes the lower bound.

- **Nodes**: `Empty Latent Image (high-res)` → `KSampler (denoise=1.0)` with `TiledDiffusion`-patched model → `VAE Decode` → `Save Image`
- **Resolution**: 1611×2416 (or any non-square ≥1.5× Qwen training res)
- **TiledDiffusion settings**: method=`Mixture of Diffusers`, `tile_width=1024`, `tile_height=1024`, `tile_overlap=352`, `tile_batch_size=1`, `rope_patch=auto`
- **KSampler**: `denoise=1.0`, `cfg≈4.5`, `steps≈20-30`, your preferred sampler
- **No ControlNet, no ReferenceLatent**

Record:
- [ ] Output saved as `R2_A_baseline_seed{N}.png`
- [ ] Number of disjoint subjects visible in the output (typically 1 per tile)
- [ ] Any console errors

### Workflow B — Hi-Res Fix recipe (no `ref_latents`, uses denoise<1.0 instead)

The recipe documented in the README. Uses a low-res pre-pass + tiled refine at low denoise. This is the reference for "what coherent output looks like with no architectural surgery". Establishes the upper bound for what we can ship today.

- **Nodes**:
  1. `Empty Latent Image (1024×1024)` → `KSampler (denoise=1.0)` (non-tiled) → `VAE Decode` → `ImageScale` to 1611×2416 → `VAE Encode` → high-res latent
  2. The high-res latent → `KSampler (denoise=0.5)` with `TiledDiffusion`-patched model → `VAE Decode` → `Save Image`
- **Same prompt, same seed for both passes**
- **TiledDiffusion settings**: same as A
- **KSampler refine**: `denoise=0.5`, otherwise same as A

Record:
- [ ] Low-res pass output saved as `R2_B_lowres_seed{N}.png`
- [ ] High-res tiled refine output saved as `R2_B_hires_seed{N}.png`
- [ ] Subject coherence: should be a single coherent canvas
- [ ] Console: VRAM peak, any warnings

### Workflow C — Experimental: feed low-res result through new `structure_latent` input

This is the actual R2 experiment. We bypass the Hi-Res Fix `denoise<1.0` lever and instead see whether the new `structure_latent` input on the `TiledDiffusion` node (which routes through Qwen's `ref_latents` channel after applying `process_latent_in`) provides per-tile spatial anchoring on **base Qwen-Image-fp8**.

- **Nodes**:
  1. Low-res pass identical to Workflow B step 1 → low-res latent
  2. `VAE Decode` → `ImageScale` to 1611×2416 → `VAE Encode` → high-res *structural* latent
  3. `Empty Latent Image (1611×2416)` → `KSampler (denoise=1.0)` with the `TiledDiffusion`-patched model where `structure_latent` input on the TiledDiffusion node is connected to step 2's encoded latent → `VAE Decode` → `Save Image`
- **Same prompt, same seed**
- **TiledDiffusion settings**: same as A, plus `structure_latent` connected
- **KSampler**: `denoise=1.0` (deliberately full denoise — we want to isolate the structure_latent effect from the denoise-strength effect)
- **Console expectation** — TiledDiffusion should print `structure_latent connected: shape=(...)` during model setup

Record:
- [ ] Output saved as `R2_C_structure_latent_seed{N}.png`
- [ ] Console line confirming `structure_latent connected: shape=...` printed
- [ ] **Coherence outcome** (a / b / c per the legend at top of doc)
- [ ] Console: VRAM peak (compare against A and B), any warnings, any crashes
- [ ] Subjective quality vs Workflow B (the Hi-Res Fix reference)

### Workflow C₂ — Cross-check: same setup using stock `ReferenceLatent` node instead

Sanity check that our `structure_latent` input is routed correctly. Replaces the new node input with the stock ComfyUI path:

- **Nodes**: same as C, but instead of connecting the high-res structural latent to `structure_latent` on the TiledDiffusion node, chain it through `ReferenceLatent` on the positive conditioning before `KSampler`. Disconnect the `structure_latent` input (or leave it connected — the two should compose; document which you chose).
- **Expected**: visually-equivalent output to C (allowing minor numerical drift from different injection ordering). If C₂ is coherent and C is not, the `structure_latent` plumbing has a bug — investigate `process_latent_in` application, slicing dim alignment, or the `ref_latents` key handling.

Record:
- [ ] Output saved as `R2_Cp2_stock_ref_latent_seed{N}.png`
- [ ] Match against C: visually-equivalent / different / one coherent + one not

### Workflow C′ — Calibration on Qwen-Image-Edit (optional, only if you have the Edit checkpoint)

Repeat Workflow C using **Qwen-Image-Edit** checkpoint instead of base Qwen-Image. Edit was trained with `ref_latents`, so this should produce a strong (a)-class result. If it doesn't, something is misconfigured upstream of the test — fix before drawing conclusions from base C.

- [ ] Output saved as `R2_Cp_edit_ref_latents_seed{N}.png`
- [ ] Outcome (expected: a)

## Decision matrix from the test

| Workflow A | Workflow B | Workflow C (base) | Workflow C′ (edit) | Implication |
|---|---|---|---|---|
| Disjoint | Coherent | Coherent (a) | Coherent | **Proceed to Phase R3.** Base Qwen accepts ref_latents as anchor; build `structure_latent` input. |
| Disjoint | Coherent | Copy-paste of low-res (b) | Coherent | Skip R3, **pivot to Phase R4** (noise structuring). Base over-fits to ref. |
| Disjoint | Coherent | NaN / garbled (c) | Coherent | Skip R3, **pivot to Phase R4**. Base rejects ref tokens. |
| Disjoint | Coherent | Coherent | Disjoint or broken | Test setup issue — fix and rerun before drawing conclusions. |
| Disjoint | Disjoint | — | — | Hi-Res Fix recipe in README is wrong or under-tuned. Investigate `denoise` and `tile_overlap` first. |

## VRAM budget check

Workflow C concatenates ref tokens to the image token sequence. For a 1024² ref + 1024² tile (Qwen patch_size=2, so 256×256 ref tokens + 256×256 tile tokens at the input layer) the attention sequence roughly doubles. Record peak VRAM for A vs B vs C — if C exceeds your card by 1.5× or more, the structure_latent path may need optional CPU-offload or a smaller-ref fallback to be practical.

## What this checklist does NOT cover

- Performance regression on the existing CN-enabled path (unchanged here, but anyone running this checklist should also confirm a known CN workflow still produces the expected coherent output as a sanity check).
- Behaviour with non-square tiles, very-high-aspect ratios, extreme overlap settings.
- SDXL / SD3 / Flux paths — this checklist is Qwen-specific.
- Sampler interactions (Dazzle KSampler, ClownsharK, etc.) — keep the sampler constant within a single test session.
