# Human Test Checklist: gaussian_weights fix (per-axis variance, symmetric midpoints)

**Target version:** v0.2.1
**Ships with commit:** `fix(node): gaussian_weights per-axis variance + symmetric midpoints` (TBD at run time; commit authored by @Adreitz, whose issue #5 supplied the corrected formula)
**Companion automated tests:** 5 tests in `tests/test_gaussian_weights.py` (all pass; includes a bug-pin where the OLD formula must fail y-symmetry, and a proof the fix changes only the y-axis plus a global scale)

## What this is

Verification steps for the Mixture-of-Diffusers blend-weight fix. The old formula (inherited from the very first upstream commit) computed y-axis spread from `tile_w`, placed the y midpoint half a cell low (a 4.5x top-vs-bottom edge-weight asymmetry at tile 32), and skipped normalization. The fix changes blend fractions at horizontal seam bands by up to 0.30 per row — every MoD render changes subtly — so a human must confirm the change is visually neutral-or-better on real renders. Anyone with a Flux.2-capable ComfyUI install can run this.

## Prerequisites

1. ComfyUI running with this node at the commit under test; a Flux.2 dev checkpoint (fp8 fine), matching CLIP/VAE.
2. **A BEFORE render from the pre-fix build** — if you updated already, check out the parent commit, restart ComfyUI, render once, then return. (Maintainers: `output/ts/HIRES_verify_00001_.png` from 2026-07-03 is the recorded BEFORE at seed 7.)
3. **Restart ComfyUI after switching code versions — every time.** The node module is cached at startup; a stale module silently renders the old behavior.
4. Clean environment: `TD_REF_NO_SLICE` and `TD_FLUX2_PACKED_RESAMPLE` must NOT be set.

   **cmd.exe**: `set TD_REF_NO_SLICE=` then `echo %TD_REF_NO_SLICE%` (expect blank/undefined)
   **PowerShell**: `Remove-Item Env:\TD_REF_NO_SLICE -ErrorAction SilentlyContinue` then `$env:TD_REF_NO_SLICE` (expect nothing)
   **POSIX**: `unset TD_REF_NO_SLICE` then `echo "$TD_REF_NO_SLICE"` (expect blank)

Reset between sections: none needed — all steps are read-only renders and script runs; outputs accumulate under ComfyUI `output/`.

## High-Value Verification (~10 minutes + one render)

### HV.1 — Automated suite passes and the bug-pin holds

Validates: the fixed math and the guarantee that a revert cannot pass silently.

- [ ] **Steps** (same across all shells; run from the node's repo root; use your ComfyUI venv python):

  ```
  python tests/test_gaussian_weights.py
  ```
- [ ] **Expected:** `ALL PASS` (5 tests). `test_1_y_symmetry` includes an assertion that the OLD formula is asymmetric — if someone reverts the fix, this file fails loudly.
- [ ] **Why this matters:** this is the mathematical contract; everything else checks how it looks.

### HV.2 — MANUAL: same-seed MoD render A/B (the core judgment)

Validates: blend-fraction changes at horizontal seam bands are visually neutral-or-better on a real render.

- [ ] **Steps:**
  1. With the FIXED build loaded (restart ComfyUI first!), load `docs/examples/hires-fix-tiled-refine.json` (seed 7, fixed; denoise 0.18; MoD 512/64) and run it unchanged.
  2. Compare against your BEFORE render (same graph, pre-fix build; maintainers: `output/ts/HIRES_verify_00001_.png`).
- [ ] **Expected (MANUAL judgment):** overall composition identical (denoise 0.18 locks structure). Look specifically at horizontal bands every ~448px (the tile-overlap rows): NO new banding, ghosting, or brightness steps; any visible difference should be neutral or smoother than before. The old code biased vertical-seam blending toward the upper tile, so if anything, subtle top-of-seam artifacts may IMPROVE.
- [ ] **Why this matters:** this is the only step that verifies "mathematically better weights" translates to "no visual regression" — the claim no unit test can make.

### HV.3 — MultiDiffusion render is UNCHANGED

Validates: the fix touches only Mixture of Diffusers (`gaussian_weights` has exactly one consumer).

- [ ] **Steps:**
  1. In the same hires graph, switch the TiledDiffusion node's `method` to `MultiDiffusion`; render on the pre-fix build (or accept the code-read: `gaussian_weights` is only assigned at `MixtureOfDiffusers.__init__`).
  2. Render the same graph on the fixed build (after restart), same seed.
- [ ] **Expected:** byte-identical images (MultiDiffusion uses uniform weights). A pixel diff of the two PNGs shows zero difference.

  **cmd.exe**: `fc /b before.png after.png` (expect `FC: no differences encountered`)
  **PowerShell**: `(Get-FileHash before.png).Hash -eq (Get-FileHash after.png).Hash` (expect `True`)
  **POSIX**: `cmp before.png after.png && echo identical`
- [ ] **Why this matters:** proves the blast radius is exactly MoD, as documented.

### HV.4 — MANUAL: non-square tiles render sanely

Validates: the newly-correct y-spread (the old code gave non-square tiles a nearly flat y-gaussian).

- [ ] **Steps:** in the hires graph set `tile_width=1024, tile_height=512, tile_overlap=64` and render (fixed build).
- [ ] **Expected (MANUAL):** a normal, seamless render — no horizontal banding at tile boundaries. (On the OLD code the y-blend at these settings was nearly uniform, masking seams differently; the point is the new code must show none either.)

### HV.5 — Restart discipline tripwire

Validates: you are actually testing the fixed module.

- [ ] **Steps:** after restarting ComfyUI, run any MoD render and check the console shows the node's startup/conversion lines (e.g. the `[TiledDiffusion] ... px per latent cell` line on Flux.2).
- [ ] **Expected:** console lines present. If you changed code and see behavior identical to before, suspect a stale module before suspecting the fix.

## What the automated tests DON'T cover

- **Visual seam quality on real renders** (HV.2/HV.4) — blend fractions changing by up to 0.30/row is provably more symmetric, but only eyes confirm "no new banding."
- **Module-cache staleness** (HV.5) — the field-proven trap; no unit test can catch a server running old code.
- **Byte-identity of non-MoD methods end-to-end** (HV.3) — code-read says untouched; the render pair proves it.
- Cross-platform rendering (verified on Windows 11 + CUDA; Linux/macOS expected identical — the change is pure NumPy math).
